# Deviations from contract/openapi.yaml and the OMB packet (B0 + B1)

Each row: what the contract or packet says, what the backend does, and why. Owner rulings are from SPEC
owner-devpod-pl-b01-impl-r1; data rules from `.spec/00-decisions.md` (A1, E1–E4).

| # | Where | Contract / packet | Implemented | Why |
|---|---|---|---|---|
| D1 | `GET /api/v1/satellite-status` (alias `/api/status`) | `x-status: release-absent` → 503 while `satellite_day_status` is absent; packet B1.14 "no-status → 503" | **200 with month-level status from the release files**: every month in `start..end` carries `value_source` / `data_source` / `status` of the release's `WORLD` rows of `aoi_month.parquet` (copied at ingest into `provenance.month_status`); months without a row are `out_of_range`. Body adds `granularity: "month"`, `day_level: "not_provided"`, `months[]` (`year_month`, `year`, `month`, `value_source`, `data_source`, `status`, `satellites[]`), `satellites[]` (satellite, instrument, first/last date in range, status counts). `days[]` appears only when a release ships `satellite_day_status.parquet` (then `granularity: "day"`, `day_level: "provided"`). `updated_at` = release load time. Defaults: `end` = last day of the release's last month, `start` = end − 29 days; range ≤ 40 years, years 2000–2100. | Ruling 6 + user line "/status 는 파일의 월 status 로". The satellites per value_source are a lookup table from m2v_meta.json wording (terra = Terra, modis_m2v = Terra+Aqua, snpp_observed = N, n20_bridge = N20, n21_bridge = N21), not a computation. |
